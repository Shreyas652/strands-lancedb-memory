# Current limitations

This document records behavior verified so far. The local 1k/10k/100k synthetic scale runs and the 100-development/400-held-out-question LongMemEval evaluation are complete. The offline CI matrix passed on Windows, macOS, and Ubuntu with Python 3.11–3.13 before the final reports were added.

- **Dependency compatibility is bounded by tested releases.** The offline store and Agent integration tests cover `strands-agents>=1.65,<1.68`, `lancedb>=0.41,<0.42`, `pyarrow>=26.0,<27`, and `filelock>=3.20,<5` at both the lowest supported versions and the newest available releases as of 25 November 2026. The frozen benchmark used the exact versions in `uv.lock`: Strands 1.65.0, LanceDB 0.41.0, PyArrow 26.0.1, and filelock 3.32.7. The compatibility tests do not rerun LongMemEval or establish behavior for versions outside these ranges.

- **Local storage only.** `s3://` and other remote URIs fail at construction. An S3 example would be misleading until an emulator and real-backend smoke pass.
- **Embeddings are supplied by the caller.** FTS works without a model. Vector and hybrid search require an `Embedder` with a declared dimension and model ID. No local embedding model is bundled or downloaded implicitly.
- **Fact updates require a stable key.** With `update_strategy="fact_key"`, the caller must pass `metadata.fact_key`. Retrieval brings the newest version of a matched key into the candidate set and ranks it first. This does not infer that differently worded unkeyed facts describe the same subject. `search_as_of` filters by asserted `valid_from`; it does not answer natural-language time questions by itself.
- **Raw ingestion identity is per Agent.** Strands restarts sequence numbers when it attaches a new Agent. Use a separate store instance and distinct `agent_run_id` for each Agent, even if they share a LanceDB directory and tenant. Reuse the ID only for replay of the same run. The store raises on conflicting IDs, but Strands can log background extraction failures rather than surfacing them to the caller, so monitor those logs.
- **Keyed retries across intervening updates need an event ID.** An implicit keyed write with the same content as the latest version is deduplicated. A return to older content becomes a new version. If an old write is retried after another update, content alone cannot distinguish the retry from a genuine revert; supply `metadata.idempotency_key` to make that replay identity explicit.
- **Local concurrency is serialized.** A process-wide reentrant lock and a cross-process OS file lock guard writable operations on the same path. The pre-lock two-process probe failed with 10/20 rows; the post-lock probe passed with 20/20. This is not evidence for network filesystem locking, S3 multi-writer operation, or high throughput. The lock acquisition deadline is 60 seconds; failures surface to callers.
- **Upstream manager errors.** Direct `store.search` raises on storage failures. Strands `MemoryManager.search` catches per-store errors, logs them, and can return an empty result. Applications should monitor these logs instead of treating every empty manager result as a true miss.
- **This benchmark does not validate production fact extraction.** The main LongMemEval run stores complete sessions as memories; it does not test the Agent's own `ModelExtractor`. The separate query-independent fact ablation reached only 28/100 correct development answers at best. On the frozen 400-question test, FTS answered 201 correctly versus 186 for FileMemoryStore, a 15-question difference under one pinned reader and model judge. The poor preference and multi-session results, plus the small paired difference, limit any general superiority claim.
- **Scale uses bulk seeding and synthetic vectors.** The 1k/10k/100k rows measure public search behavior and direct LanceDB bulk-load throughput on one Windows host, not the public store's `add` throughput or embedding quality. The measured IVF_FLAT index lost top-10 recall and was slower at some sizes. No production ANN default follows from these measurements.
